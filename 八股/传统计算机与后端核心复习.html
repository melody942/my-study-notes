第一部分 操作系统与 Linux

1. 操作系统基本原理

核心概念

  • 操作系统：管理 CPU、内存、文件和设备，并为应用提供隔离、保护和抽象。
  • 用户态：应用程序运行的低权限环境，不能直接访问硬件和内核数据。
  • 内核态：内核运行的高权限环境，可以管理硬件和系统资源。
  • 系统调用：用户程序请求内核服务的正式入口，例如 read、write、fork、mmap。
  • 中断：外部设备或时钟通知 CPU；异常：当前指令执行引起的处理，例如缺页异常。
  • 从用户态进入内核态的常见原因：系统调用、硬件中断、异常。

关键关系与答案

为什么要区分用户态和内核态？

为了保护系统资源。普通程序不能直接修改页表、访问任意设备或破坏其他进程的内存；需要操作系统完成检查后，再以更高权限执行。

系统调用和普通函数调用有什么区别？

普通函数调用通常只在用户态跳转；系统调用需要切换到内核态，由内核检查参数、执行服务，再切回用户态，因此开销更大。

中断和系统调用有什么区别？

系统调用通常由程序主动发起，中断通常由硬件或时钟异步触发；异常则是当前指令执行过程中产生的同步事件。

易错点

  • 用户态/内核态切换不等于进程切换。
  • 系统调用不一定会阻塞，是否阻塞取决于具体调用和资源状态。
  • printf、malloc 可能间接触发系统调用，但不能简单把它们都等同于系统调用。

2. 进程、线程与协程

核心概念

  • 进程：资源分配和隔离的基本单位，拥有独立虚拟地址空间。
  • 线程：CPU 调度的基本单位，是进程中的实际执行流。
  • 线程共享：代码、全局数据、堆、打开的文件等。
  • 线程私有：栈、程序计数器、寄存器、线程局部存储。
  • 协程：运行在线程之上的用户态执行单元，通常由运行时调度。
  • 进程重隔离，线程重共享，协程重低成本切换。

关键关系与答案

为什么进程是资源分配单位，线程是调度单位？

进程拥有地址空间、文件和权限等资源；调度器真正选择并执行的是进程中的线程，所以线程是 CPU 调度的基本单位。

为什么线程切换通常比进程切换轻？

同一进程内的线程共享地址空间，通常不需要切换页表；进程切换还可能带来地址空间切换和 TLB 影响。但线程切换也有寄存器保存、调度和缓存失效成本。

协程能实现并行吗？

单线程上的协程只能实现并发，不能同时使用多个核心；需要把任务调度到多个线程上，才能结合线程实现并行。

CPU 密集型和 IO 密集型任务如何选择？

CPU 密集型更依赖多核并行和线程池；IO 密集型适合协程或异步 IO，因为等待期间可以运行其他任务。

易错点

  • 线程共享堆，但不共享栈。
  • 协程中执行阻塞调用，仍可能阻塞承载它的线程。
  • 线程越多不一定越快，可能增加上下文切换和锁竞争。

3. 调度、同步与进程通信

核心概念

  • 调度算法关注公平性、响应时间、吞吐量和优先级。
  • 常见算法：先来先服务、短作业优先、时间片轮转、优先级调度、CFS。
  • 临界区：访问共享资源的代码区域。
  • 互斥保证同一时间只有一个执行者；同步保证执行顺序或条件满足。
  • 常见同步工具：互斥锁、读写锁、条件变量、信号量、原子操作。
  • 进程通信：管道、消息队列、共享内存、信号、Socket。

关键关系与答案

互斥锁和信号量有什么区别？

互斥锁主要保护临界区，通常由加锁线程解锁；信号量是一个计数器，既可表示资源数量，也可用于线程之间的通知。

为什么共享内存速度快？

数据映射到多个进程的地址空间后，双方可以直接访问同一份内存，减少内核介入和数据复制；但同步和生命周期管理需要应用自己负责。

条件变量解决什么问题？

它让线程在条件不满足时睡眠，条件满足后被唤醒，避免线程不断轮询。条件变量必须和互斥锁配合，并用循环重新检查条件。

进程通信为什么比线程通信复杂？

不同进程地址空间隔离，不能直接读写对方数据；线程处于同一地址空间，可以共享变量，但需要同步来避免数据竞争。

易错点

  • 原子操作只保证特定操作的原子性，不会自动保护一组复杂逻辑。
  • 读多写少不代表一定使用读写锁，锁竞争和写入比例需要结合压测判断。
  • 共享内存快，但不是“天然安全”。

4. fork、写时复制与死锁

核心概念

  • fork 创建子进程；父子进程拥有独立的进程描述信息和地址空间视图。
  • 写时复制 COW：创建进程时先共享物理页，某一方写入时再复制页面。
  • 僵尸进程：子进程已退出，但父进程还没有回收其退出信息。
  • 孤儿进程：父进程先退出，子进程被其他进程接管。
  • 死锁四条件：互斥、占有且等待、不可剥夺、循环等待。

关键关系与答案

fork 后父子进程是否立即复制全部内存？

不会。通常先共享物理页并标记为只读，只有某一方写入时才复制对应页面，因此 COW 可以降低创建进程的初始成本。

僵尸进程为什么仍然占资源？

它已经不再执行，但内核仍保留退出码等信息，等待父进程调用 wait 或相关接口回收。大量僵尸进程会耗尽进程表项。

如何避免死锁？

可以破坏四个必要条件，例如统一加锁顺序、减少锁的持有时间、使用 try_lock、设置超时，或在系统层面检测并解除死锁。

不安全状态是不是已经死锁？

不是。不安全状态表示未来可能进入死锁；死锁表示当前已经存在无法继续推进的资源等待环。

易错点

  • fork 后父子进程谁先执行没有固定保证。
  • kill -9 不能直接杀掉处于不可中断睡眠等特殊状态的进程。
  • 资源分配图有环不总是等于死锁，取决于资源类型和实例数量。

5. 虚拟内存、文件系统与 IO

核心概念

  • 虚拟内存为每个进程提供独立、连续的地址空间视图。
  • 页表负责虚拟地址到物理地址的转换，TLB 缓存常用转换结果。
  • 缺页中断发生后，内核检查访问是否合法，必要时从磁盘加载页面。
  • inode 保存文件元数据和数据块索引；文件名主要由目录维护。
  • 文件描述符是进程访问打开文件的整数句柄。
  • 零拷贝的目标是减少用户态/内核态之间的数据复制和上下文切换。

关键关系与答案

mmap 和 sendfile 有什么区别？

mmap 把文件映射到进程地址空间，应用可以像访问内存一样读写；sendfile 允许内核直接把文件数据发送到 Socket，适合文件转发，通常减少用户态参与。

为什么 inode 不保存文件名？

目录负责把文件名映射到 inode，文件本身只保存元数据和数据块信息。这样可以支持一个 inode 被多个硬链接引用。

删除文件后数据一定消失吗？

删除通常只是删除目录项并减少链接计数；只要仍有打开的文件描述符或其他硬链接，数据仍可能存在。链接计数归零且没有进程打开后，空间才可回收。

缺页中断一定是错误吗？

不一定。合法页面尚未装入物理内存时也会产生缺页中断；访问非法地址才会进一步触发段错误。

易错点

  • 虚拟内存不是把所有数据都放进磁盘。
  • 零拷贝不代表系统完全没有任何数据复制。
  • 文件描述符、打开文件表和 inode 是不同层次的对象。

第二部分 计算机网络

6. 网络分层与地址体系

核心概念

  • 应用层处理业务协议，传输层处理端到端传输，网络层处理寻址和路由，链路层处理局部网络传输。
  • IP 地址标识网络层主机接口，MAC 地址标识链路层接口。
  • ARP 根据 IPv4 地址寻找同一局域网中的 MAC 地址。
  • ICMP 用于差错报告和网络诊断。
  • NAT 把私有地址和公网地址进行转换。
  • 子网掩码决定网络部分和主机部分。

关键关系与答案

为什么既需要 IP 又需要 MAC？

IP 用于跨网络路由，MAC 用于当前链路上的帧传输。数据每经过一个路由器，链路层 MAC 通常会变化，而目标 IP 通常保持不变。

ping 的基本过程是什么？

发送端通过 ICMP Echo Request 探测目标，目标返回 Echo Reply。目标不可达、被防火墙拦截或路由异常时都可能没有响应，因此 ping 不等于应用服务一定正常。

NAT 解决什么问题？

它让多个私有地址共享公网地址，并在转换表中记录连接映射；代价是破坏端到端可达性，使入站连接、协议兼容和排障更复杂。

易错点

  • DNS、ARP、路由不是同一层的问题。
  • IP 地址不等于设备永久身份，网络环境变化时地址可能变化。
  • ping 通只能说明某种 ICMP 路径可达，不能证明 TCP 端口或应用正常。

7. TCP、UDP 与可靠传输

核心概念

  • TCP 面向连接、可靠、有序，提供字节流、流量控制和拥塞控制。
  • UDP 无连接，不保证可靠、有序和不重复，报文边界保留，开销较低。
  • TCP 使用序列号和确认号识别数据位置与接收进度。
  • 滑动窗口允许发送方在未收到全部确认前持续发送。
  • 流量控制保护接收方，拥塞控制保护网络。

关键关系与答案

TCP 为什么是字节流？

TCP 只保证字节按序到达，不保留应用层消息边界。应用一次写入的数据可能被拆成多个包，也可能和其他写入合并，因此需要应用层定义消息长度或分隔符。

流量控制和拥塞控制有什么区别？

流量控制根据接收窗口限制发送速度，防止接收方处理不过来；拥塞控制根据网络拥塞情况调整发送速度，防止网络被压垮。

UDP 如何实现可靠传输？

在应用层增加序列号、确认、超时重传、校验、流量控制和拥塞处理。可靠性来自上层设计，而不是 UDP 本身。

QUIC 解决什么问题？

QUIC 基于 UDP 实现可靠传输、加密和多路复用，减少握手延迟，并能缓解 TCP 层队头阻塞和连接迁移问题。

易错点

  • TCP 可靠的是传输过程，不代表业务处理一定成功。
  • UDP 不等于一定更快，实际还受网络、协议栈和应用处理影响。
  • TCP 没有消息边界，UDP 有报文边界。

8. TCP 连接建立、关闭与异常

核心概念

  • 三次握手：同步双方初始序列号，并确认双方收发能力。
  • 四次挥手：TCP 两个方向可以独立关闭。
  • SYN_SENT、SYN_RECV、ESTABLISHED、FIN_WAIT、CLOSE_WAIT、TIME_WAIT 是常见状态。
  • TIME_WAIT 通常由主动关闭方进入。
  • TCP Keepalive 用于探测空闲连接；HTTP Keep-Alive 用于复用连接。

关键关系与答案

为什么需要三次握手？

两次只能让服务端发送 SYN+ACK，不能充分确认客户端已经收到并具备接收能力。第三次 ACK 让双方都确认对方的收发状态和序列号。

为什么挥手通常需要四次？

一方发送 FIN 只代表自己不再发送数据，仍可能继续接收；双方的发送方向需要分别关闭，因此通常需要两个 FIN 和两个 ACK。

CLOSE_WAIT 很多说明什么？

对端已经关闭连接，但本端应用没有及时调用 close，常见原因是连接泄漏或异常路径没有释放资源。

TIME_WAIT 为什么存在？

它保证最后的 ACK 丢失时可以重传，并等待旧报文在网络中消失，避免影响后续使用相同四元组的连接。

易错点

  • TIME_WAIT 通常出现在主动关闭方。
  • HTTP Keep-Alive 不是 TCP Keepalive。
  • TCP 连接建立成功不代表应用已经完成业务处理。

9. HTTP、HTTPS 与 Web 通信

核心概念

  • HTTP 由请求行、头部、空行和消息体组成。
  • GET 通常用于获取资源，POST 通常用于提交数据；是否幂等取决于接口语义。
  • 2xx 表示成功，3xx 表示重定向，4xx 通常表示请求问题，5xx 通常表示服务端问题。
  • Cookie 由客户端保存，Session 状态通常保存在服务端，Token 由客户端携带身份信息。
  • HTTPS = HTTP + TLS，提供身份验证、机密性和完整性。

关键关系与答案

GET 和 POST 的区别是什么？

GET 语义上用于获取资源，参数通常体现在 URL 中；POST 通常用于提交或创建资源。安全性、幂等性和缓存行为不能只按方法名称绝对判断，最终取决于接口设计。

HTTPS 的 TLS 握手做了什么？

客户端验证服务端证书，双方协商密码套件并完成密钥交换，后续主要使用对称密钥加密通信，同时校验数据完整性。

Cookie、Session、Token、JWT 如何区分？

Cookie 是客户端保存和发送数据的机制；Session 是服务端保存会话状态的方式；Token 是客户端携带的凭证；JWT 是一种具有固定结构、通常可自包含声明的 Token 格式。

HTTP/2 为什么更快？

它支持二进制帧、多路复用、头部压缩和流优先级；但 TCP 层丢包仍可能阻塞同一连接上的所有流。HTTP/3 使用 QUIC，减少了这种影响。

易错点

  • HTTPS 只保护传输链路，不负责业务授权。
  • JWT 签名保证完整性和来源，不等于内容加密。
  • HTTP 200 不一定代表业务成功，业务状态需要单独表达。

10. DNS、缓存、代理与网络 IO

核心概念

  • DNS 解析通常经过浏览器、操作系统、本地 DNS、递归 DNS 和权威 DNS。
  • 强缓存由 Cache-Control 等规则决定是否直接使用本地副本。
  • 协商缓存通过 ETag 或 Last-Modified 与服务端确认资源是否变化。
  • CDN 把内容缓存到靠近用户的节点。
  • 正向代理代表客户端访问外部服务，反向代理代表服务端接收请求。
  • select、poll、epoll 都用于 IO 多路复用。

关键关系与答案

强缓存和协商缓存有什么区别？

强缓存命中后可以直接使用本地资源，不必请求服务器；协商缓存仍会发送请求，由服务器判断资源是否变化，未变化时返回 304。

epoll 为什么适合大量连接？

它维护关注的文件描述符和就绪事件，返回发生事件的连接，避免每次都线性扫描全部连接。但业务处理阻塞、锁竞争和数据拷贝仍可能成为瓶颈。

从 URL 到页面显示经过哪些步骤？

解析域名、建立连接、TLS 握手、发送 HTTP 请求、服务端处理、返回资源、浏览器解析 HTML/CSS/JS 并渲染。实际还可能经过 CDN、代理、缓存和多个后端服务。

易错点

  • CDN 缓存的是派生内容，不能替代业务事实源。
  • epoll 只负责事件通知，不负责业务逻辑。
  • 缓存命中不代表数据永远是最新的。

第三部分 数据库与后端系统

11. 数据库与 SQL

核心概念

  • 数据库保存结构化数据，DBMS 负责查询、并发、权限和恢复。
  • 关系型数据库用表、行、列和关系组织数据。
  • 主键唯一标识记录，外键表达引用关系，约束保证数据合法性。
  • SQL 的逻辑处理顺序通常可记为：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。
  • 范式减少冗余和更新异常，反范式用冗余换取查询效率。

关键关系与答案

WHERE 和 HAVING 有什么区别？

WHERE 在分组前过滤明细行，HAVING 在分组后过滤聚合结果。

左连接后为什么可能变成内连接？

如果把右表条件写在 WHERE 中，右表为空的行会被过滤掉。需要保留左表记录时，应判断条件是否应该放在 ON 中。

为什么不把所有数据放在一张表？

单表会产生大量冗余和更新异常；拆表可以表达关系和约束，但 JOIN 过多又会增加查询成本，因此需要根据访问模式适度反范式。

易错点

  • NULL 不是普通值，不能用 = NULL 判断。
  • NoSQL 不是“不需要结构”，而是围绕其他数据模型和访问模式设计。
  • 范式和反范式是取舍，不是绝对优劣。

12. 索引与查询性能

核心概念

  • 索引是额外维护的数据结构，用空间和写入成本换取更少的数据扫描。
  • B+ 树树高较低，适合页式存储、范围查询和有序遍历。
  • 联合索引通常遵循从左到右的匹配规律。
  • 回表是先查二级索引，再根据主键查完整记录。
  • 覆盖索引表示查询所需列都在索引中，可以减少回表。
  • EXPLAIN 关注访问类型、索引、预计行数、排序和临时表。

关键关系与答案

为什么索引不是越多越好？

索引占用空间，并且插入、更新、删除时都要维护。重复、低选择性的索引还会增加优化器和写入成本。

索引为什么可能失效？

常见原因有：联合索引不满足左侧条件、对列做函数或计算、隐式类型转换、前缀模糊匹配、选择性太低，或优化器认为全表扫描更便宜。

为什么深分页慢？

OFFSET 很大时，数据库通常要先扫描并跳过大量记录。可以根据稳定排序键使用游标分页或范围分页。

易错点

  • 命中索引不等于查询一定快。
  • B+ 树适合范围查询，哈希索引主要适合等值查询。
  • 不能只看索引定义，要结合执行计划和实际扫描行数。

13. 事务与并发控制

核心概念

  • 原子性：事务中的操作要么全部成功，要么全部失败。
  • 一致性：事务前后满足约束和业务不变量。
  • 隔离性：并发事务之间按照隔离级别产生可见性边界。
  • 持久性：提交结果在故障后可以恢复。
  • 脏读、不可重复读、幻读是典型并发读问题。
  • 锁通过限制访问保护数据，MVCC 通过保存版本让读写更好地并行。

关键关系与答案

隔离级别如何选择？

隔离级别越高，读一致性通常越强，但锁等待或版本管理成本也可能更高。应根据业务是否允许旧数据、并发量和写冲突选择，不能简单认为越高越好。

乐观锁和悲观锁有什么区别？

悲观锁假设冲突会发生，访问前先加锁；乐观锁假设冲突较少，更新时检查版本号，冲突后重试或失败。高冲突场景更适合强保护，低冲突场景可以采用乐观方式。

事务能保证跨服务一致性吗？

单库事务只能覆盖自己的资源。跨服务还需要幂等、可靠事件、补偿、Outbox 或分布式事务方案，不能只依赖本地事务。

易错点

  • 数据库一致性和分布式副本一致性不是同一个概念。
  • 加了事务不等于自动具备幂等性。
  • MVCC 不代表完全没有锁，当前读和写操作仍可能加锁。

14. Redis 与缓存

核心概念

  • String 适合简单值和计数，Hash 适合对象字段，List 适合队列，Set 适合去重，ZSet 适合排序。
  • 过期删除可以是惰性删除和定期删除，内存不足时还会触发淘汰策略。
  • RDB 是快照，AOF 记录写操作；持久化方案需要在恢复速度和数据完整性之间取舍。
  • 主从复制提供读扩展和故障基础，哨兵负责监控和切换，Cluster 负责分片。
  • Cache-Aside 通常是读缓存，未命中查库并回填；写入常见做法是更新数据库后使缓存失效。

关键关系与答案

缓存穿透、击穿、雪崩分别是什么？

穿透是大量请求查询不存在的数据；击穿是某个热点 Key 失效时大量请求同时查库；雪崩是大量 Key 同时失效或缓存整体不可用。对应措施包括空值/布隆过滤器、互斥重建/逻辑过期、随机过期/限流/多级缓存。

为什么通常不把缓存作为唯一事实源？

缓存可能过期、淘汰、丢失或与数据库短暂不一致。核心数据通常需要可靠持久化来源；如果缓存就是主存储，则必须单独设计持久化、恢复和一致性。

更新数据库和缓存的顺序能不能绝对确定？

不能。常见 Cache-Aside 是先写数据库再让缓存失效，但并发读写可能产生旧值回填，需要版本号、延迟双删、变更订阅或短 TTL 等方案结合处理。

易错点

  • 缓存命中不代表数据永远正确。
  • 分布式锁只能减少并发重建，不能替代数据一致性设计。
  • 大 Key、热 Key、淘汰策略和网络带宽都可能成为瓶颈。

15. 消息队列

核心概念

  • 消息队列用于异步解耦、削峰填谷、失败重试和事件传播。
  • 可靠链路包含生产确认、持久化、消费确认和失败处理。
  • 至少一次投递意味着消费者可能收到重复消息。
  • 幂等可以通过业务唯一键、去重表、状态机或数据库唯一约束实现。
  • 消息系统还要处理顺序、积压、重试、死信和消费进度。

关键关系与答案

为什么消息重复消费是常态？

生产者重试、消费者处理成功但确认丢失、网络超时等都会导致同一消息再次投递。工程上通常接受至少一次投递，再由消费者保证幂等。

如何保证消息不丢？

生产端确认消息已被持久化或接收，Broker 做持久化和副本，消费端成功处理后再确认，并对失败消息重试或进入死信。每一环都要有失败恢复方案。

消息顺序如何保证？

把需要保持顺序的消息路由到同一分区或队列，并保证同一分区内按顺序消费；同时要处理重试、并发消费者和异常消息。

易错点

  • “Exactly Once”通常只在局部语义成立，不能直接等同于业务端到端只执行一次。
  • 消费成功后再确认，重复是可能的；先确认再处理，则可能丢失。
  • 消息队列不能自动解决跨服务事务和业务幂等。

16. 分布式系统与服务治理

核心概念

  • 分布式系统的困难来自网络延迟、部分失败、时钟差异、重复请求和数据分散。
  • CAP 讨论网络分区发生时，一致性和可用性的取舍。
  • 分布式锁需要互斥、过期、续期、故障恢复和误删保护。
  • 分库分表解决容量和并发问题，但会增加路由、跨库查询和事务复杂度。
  • 高可用依赖冗余、健康检查、故障转移、限流、降级和恢复。
  • 服务治理关注服务发现、负载均衡、超时、重试、熔断和观测。

关键关系与答案

超时、重试、熔断、降级分别解决什么？

超时限制单次等待；重试处理临时失败；熔断在依赖持续失败时快速失败；降级在资源不足或依赖异常时返回较弱但可接受的结果。重试必须配合退避、抖动和幂等。

为什么不能无限重试？

重试会增加依赖压力，形成重试风暴。应限制次数、设置退避和总超时，并区分可重试错误和不可重试错误。

什么时候考虑微服务？

当领域边界、团队职责、发布节奏、扩缩容或故障隔离确实不同，并且团队能承担分布式运维成本时再拆分。组件越多不代表系统越先进。

易错点

  • CAP 不是“只能选两个产品特性”的简单菜单。
  • 高可用不等于永不失败，而是失败时能发现、隔离、切换和恢复。
  • 分布式锁、事务和幂等解决的问题不同，不能互相替代。

17. 工程化、可观测性与安全

核心概念

  • 容器解决环境封装和交付一致性，不等于虚拟机。
  • 日志记录单次细节，指标反映整体趋势，Trace 串联一次请求跨服务路径。
  • 认证回答“你是谁”，授权回答“你能做什么”，审计记录“谁做了什么”。
  • 哈希是单向摘要，加密保护机密性，签名证明来源和完整性。
  • 安全设计需要最小权限、输入校验、输出编码、密钥管理和敏感信息脱敏。

关键关系与答案

如何排查一个接口变慢？

先按 Trace 拆分 DNS、建连、网关排队、应用计算、缓存、数据库和外部依赖，再结合 P95/P99、错误率、线程池、连接池、CPU、内存、锁等待和消息积压定位。

日志、指标、Trace 如何配合？

指标负责发现问题范围和趋势，Trace 定位一次请求在哪个阶段变慢，日志提供该阶段的具体上下文。三者应通过 request ID 或 trace ID 关联。

哈希、加密、签名有什么区别？

哈希通常不可逆，用于摘要和校验；加密可以用密钥还原，用于保护机密性；签名由私钥生成，其他人用公钥验证来源和完整性。

易错点

  • HTTPS 不能替代服务端权限控制。
  • 只看平均延迟可能掩盖严重的尾延迟。
  • 密码不能直接加密存储或明文存储，应使用专门的密码哈希方案和盐。

第四部分 C++ 核心

18. C++ 语言与编译链接

核心概念

  • const 表示只读约束，static 影响生命周期、链接性或类成员语义，volatile 不等于线程安全。
  • inline 主要影响 ODR 和多重定义规则，不保证编译器一定内联。
  • 指针保存地址，引用是已有对象的别名，nullptr 表示空指针。
  • 四种强制转换分别用于不同的安全边界，不能混用。
  • 编译过程通常经历预处理、编译、汇编、链接。
  • ODR 要求实体在程序中遵守定义规则；静态库和动态库解决链接与部署的不同问题。

关键关系与答案

指针和引用有什么区别？

指针是对象，可以为空、重新指向并进行指针运算；引用通常必须绑定对象，不能重新绑定。底层实现可能相似，但语义和使用约束不同。

static 有哪些含义？

局部静态变量延长生命周期；文件级静态变量限制内部链接；类静态成员属于类而非单个对象。具体含义要结合出现位置判断。

为什么需要 extern "C"？

C++ 支持函数重载，符号名通常会被修饰；extern "C" 使用 C 链接约定，便于 C/C++ 之间调用。

易错点

  • volatile 主要表达外部可见变化，不保证原子性和线程同步。
  • const_cast 去掉只读属性后，修改真正的 const 对象可能是未定义行为。
  • 头文件中定义非 inline 的全局实体可能造成重复定义。

19. C++ 内存与对象模型

核心概念

  • 栈通常保存自动对象，堆用于动态分配，静态区保存全局和静态对象。
  • new 通常包含分配和构造，delete 包含析构和释放；malloc/free 只处理原始内存。
  • 对齐保证对象按适合硬件访问的边界布局。
  • 构造函数初始化对象，析构函数释放对象拥有的资源。
  • Rule of 3/5/0 连接着析构、拷贝和移动语义。
  • this 指向当前对象，虚函数通过虚表实现运行时多态。

关键关系与答案

new 和 malloc 有什么区别？

new 返回指定类型并调用构造函数，失败通常抛出异常；malloc 返回原始字节并返回空指针表示失败，不负责构造。释放方式必须匹配。

什么是深拷贝和浅拷贝？

浅拷贝只复制成员值，指针成员仍指向同一资源；深拷贝复制资源本身。拥有资源的类如果使用默认拷贝，可能造成重复释放或共享修改。

为什么基类析构函数常声明为 virtual？

通过基类指针删除派生类对象时，虚析构可以按照派生类到基类的顺序完整析构；否则可能只调用基类析构函数。

虚函数和重载有什么区别？

重载在同一作用域通过参数列表区分，主要是编译期选择；虚函数通过继承和动态类型实现运行时分派。

易错点

  • 只要类中有指针成员，不一定就必须深拷贝，关键是是否拥有资源。
  • 析构函数不能随意抛出异常。
  • 多态调用依赖虚函数和正确的对象生命周期，构造/析构期间不会按普通方式调用派生类虚函数。

20. 现代 C++、资源管理与 STL

核心概念

  • 左值有稳定身份，右值通常表示临时值或可被移动的资源。
  • 移动语义转移资源所有权，避免不必要的深拷贝。
  • 完美转发通过模板和 std::forward 保留实参的值类别。
  • Lambda 是可调用对象，捕获决定闭包如何使用外部变量。
  • RAII 把资源生命周期绑定到对象生命周期。
  • 智能指针表达所有权：unique_ptr 独占，shared_ptr 共享，weak_ptr 不拥有。
  • STL 容器要结合访问、插入、删除和内存稳定性选择。

关键关系与答案

移动语义为什么能提升性能？

它把临时对象持有的资源直接转移给目标对象，避免重新分配和复制大量数据。移动后原对象仍必须处于可析构、可赋值的有效状态。

unique_ptr 和 shared_ptr 如何选择？

默认优先 unique_ptr，所有权清晰、开销小；确实需要多个对象共同管理生命周期时才使用 shared_ptr。不需要所有权的观察关系使用 weak_ptr 或裸指针/引用。

为什么 shared_ptr 仍可能造成内存泄漏？

两个对象互相持有 shared_ptr 会形成引用环，引用计数永远不为零。应让其中一方使用 weak_ptr。

vector 和 list 如何选择？

vector 连续存储、缓存友好、随机访问快，通常是默认选择；list 插入删除节点稳定，但额外指针和缓存不友好，只有明确需要时才使用。

易错点

  • std::move 只是类型转换，不保证一定发生移动。
  • shared_ptr 的线程安全只覆盖控制块，不代表被管理对象的读写线程安全。
  • 迭代器失效规则取决于容器和操作，不能一概而论。

21. C++ 并发与算法

核心概念

  • 互斥保证临界区不能被同时执行，可见性保证一个线程能看到另一个线程的写入，有序性约束操作顺序。
  • 原子操作适合简单共享状态，复杂不变量仍需锁或更高层同步。
  • acquire/release 等内存序控制跨线程的可见性和排序。
  • 自旋锁适合极短临界区，持锁时间长时会浪费 CPU。
  • 常见数据结构：数组、链表、栈、队列、哈希表、树、堆、图。
  • 常见算法：排序、二分、双指针、滑动窗口、DFS/BFS、动态规划。

关键关系与答案

原子操作能替代互斥锁吗？

只能替代满足特定原子不变量的简单操作。多个变量需要保持一致，或临界区包含复杂逻辑时，仍需要锁、事务或其他同步机制。

自旋锁和互斥锁如何选择？

临界区极短且等待不会导致线程长期占用 CPU 时可以自旋；可能长时间等待或线程数多时，应让线程睡眠，使用互斥锁更合适。

稳定排序是什么意思？

相同关键字的元素在排序后保持原相对顺序。是否稳定会影响多关键字排序和业务结果。

易错点

  • 时间复杂度相同不代表实际性能相同，还要考虑常数、缓存和内存分配。
  • 无锁编程不等于没有同步问题，ABA、内存回收和内存序都需要处理。
  • 线程安全容器不等于一组复合操作天然原子。

第五部分 设计模式与系统设计

22. 面向对象设计原则

核心概念

  • 封装隐藏变化，继承表达“是一个”，多态允许通过抽象接口使用不同实现。
  • 单一职责：一个模块只有一个主要变化原因。
  • 开闭原则：对扩展开放，对修改关闭。
  • 里氏替换：子类型应能替换父类型而不破坏正确性。
  • 接口隔离：客户端不应依赖不需要的接口。
  • 依赖倒置：高层依赖抽象，而不是依赖具体实现。
  • 组合通常比继承更灵活，因为可以在运行时替换组件。

关键关系与答案

为什么组合通常优于继承？

继承把父子类实现和生命周期绑定得更紧，容易形成脆弱基类；组合通过持有接口或组件降低耦合，也更容易替换实现。但稳定的“是一个”关系仍然适合继承。

开闭原则是不是完全不能修改旧代码？

不是。它强调把稳定部分和变化点隔离，新增行为尽量通过扩展实现；如果旧抽象本身错误，修改设计比盲目扩展更合理。

易错点

  • SOLID 是设计指导原则，不是必须逐条机械套用的规则。
  • 引入抽象层也有复杂度，不能为了设计模式而设计模式。

23. 常用设计模式与架构模式

核心概念

  • 创建型：工厂、抽象工厂、建造者、单例、原型。
  • 结构型：适配器、装饰器、代理、外观、组合、桥接、享元。
  • 行为型：观察者、策略、模板方法、责任链、状态、命令、迭代器。
  • Reactor 由事件循环监听就绪事件并分发处理；Proactor 更强调异步操作完成通知。
  • 生产者—消费者通过队列解耦生产速度和消费速度。
  • 线程池、连接池、对象池通过复用资源降低创建和销毁成本。

关键关系与答案

适配器、装饰器、代理有什么区别？

适配器改变接口以兼容已有代码；装饰器在不改变接口的情况下叠加功能；代理通常代表对象访问目标，并可控制权限、延迟加载或远程调用。

观察者和发布订阅有什么区别？

观察者通常是对象之间的直接订阅关系；发布订阅通过中间事件总线解耦发布者和订阅者，更适合跨模块或跨服务通信。

Reactor 和 Proactor 的主要区别？

Reactor 通知“IO 已就绪”，应用再执行读写；Proactor 通知“IO 已完成”，应用处理完成结果。具体实现还取决于操作系统和框架。

易错点

  • 模式名称不重要，重要的是它解决的变化点和引入的代价。
  • 单例可能带来全局状态、测试困难和并发初始化问题。
  • 连接池、线程池需要处理上限、超时、泄漏和关闭。

24. 系统设计与请求链路

核心概念

  • 一次请求通常经过 DNS、TCP/TLS、网关、应用进程、缓存、数据库、消息队列和响应观测。
  • 同步链路处理必须立即确定的核心事实；异步链路处理可延后、可重试的副作用。
  • 数据库通常保存核心事实，缓存服务热点读取，消息队列承担异步解耦。
  • 可靠系统需要超时、重试、幂等、限流、熔断、降级和监控。
  • 系统设计要同时考虑正确性、性能、可用性、成本和运维复杂度。

关键关系与答案

如何设计一个下单接口？

同步完成鉴权、参数校验、价格和库存校验、订单核心状态写入；事务提交后再通过可靠事件或 Outbox 触发通知、积分、搜索索引等异步副作用。接口需要幂等键，消费端也要幂等。

如何定位接口变慢？

先按 Trace 拆分网络、网关、排队、应用计算、缓存、数据库和外部依赖，再结合 P95/P99、线程池、连接池、锁等待和资源指标定位瓶颈。

为什么不能一开始就堆缓存、MQ 和微服务？

每个组件都会增加部署、监控、故障和一致性成本。应先用满足当前约束的简单方案，再根据真实瓶颈演进。

易错点

  • “高并发”必须落到 QPS、数据量、峰值、延迟和一致性要求。
  • 返回 HTTP 200 不等于业务成功。
  • 异步不等于不需要一致性和可靠投递。

25. 高频概念对比

对比 记忆重点
进程 / 线程 / 协程 隔离资源 / 执行调度 / 用户态并发
TCP / UDP 可靠有序字节流 / 无连接报文传输
HTTP Keep-Alive / TCP Keepalive 连接复用 / 空闲探活
Cookie / Session / Token / JWT 客户端载体 / 服务端状态 / 身份凭证 / Token 格式
缓存 / 数据库 / 消息队列 性能优化 / 事实存储 / 异步解耦
乐观锁 / 悲观锁 / MVCC 更新时检查 / 访问前加锁 / 多版本读取
同步 / 异步 当前调用等待结果 / 任务交给后续处理
限流 / 熔断 / 降级 控制流量 / 快速隔离失败依赖 / 返回较弱结果

26. 高频排障顺序

  1. 先确认现象：错误率、平均延迟、P95/P99、吞吐是否变化。
  2. 再拆分链路：客户端、网络、网关、应用、缓存、数据库、消息和外部依赖。
  3. 再看资源：CPU、内存、磁盘、连接池、线程池、锁等待、队列积压。
  4. 最后结合日志、指标和 Trace 定位根因，并验证修复是否改变真实指标。
